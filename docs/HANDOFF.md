## 1. 목적

### 공모전
- **2026 현대자동차그룹 차량용 앱 개발 공모전** (대학생 부문). 플랫폼: **Pleos Connect** (현대차그룹 차세대 차량 OS, Android Automotive 기반)
- 심사 기준: **차량 특화성 · 창의성 · 기술 활용성(Pleos SDK) · 사업성**
- 일정: 1차 기획서 접수 11/15 → 1차 결과 11/23 → **2차 PT 12/3~4 (동작하는 앱 필수, 에뮬레이터 시연 가능)** → 최종 12/18
- 제출물: 기획서, (선택) 시연 영상, GitHub 저장소 + `팀명_앱이름_release.apk` + README

### 앱이 해결하는 문제
익숙한 지역에서 내비 추천 경로 대신 **내가 아는 길**로 가고 싶을 때, 기존 내비는 경유지를 "들르는 장소"로만 넣을 수 있어
"이 도로를 지나서 가고 싶다"를 표현하기 어렵고, 두 경로를 나란히 비교하기도 어렵다.

### 기능 우선순위 (중요: 이 순서를 지킬 것)
1. **메인 — 길 콕 찍기 + 경로 비교:** 지도에서 지나고 싶은 길을 탭 → 그 길을 지나는 경로를 추천 경로와 비교 → 기본 내비로 안내
2. **보조 — 경로 주변 명소:** 고른 경로 주변 명소를 지도에서 보고 경유지로 추가
3. **보조 — 운전 습관 피드백:** 주행 기록으로 가속·감속 습관을 피드백 (연비 "예측"이 목적이 아님. 아래 4장 참고)

## 2. 현재 구현된 기능 (v1.1)

| 경로 | 목적지 선택(검색·지도 탭·데모 기본값 코엑스) → **추천 경로 자동 표시** | 동작 |
| 경로 | 지도 탭 → **콕 지점** 추가(최대 2곳), 도로 이름 자동 표시(OSM 역지오코딩) → 길콕 경로 자동 계산 | 동작 |

| 경로 | 경로가 콕 지점을 실제로 지나는지 검증(60m 이내, 순서 포함) → "콕 지점 통과 ✓" | 동작 |
| 경로 | 경유지 2곳일 때 **총거리가 짧은 방문 순서** 자동 선택 | 동작 |
| 경로 | **주변 명소 보기**: TourAPI로 테마(볼거리/자연·산책/먹거리·카페/행사)별 상위 5곳을 지도에 번호+이름표로 표시, 목록 탭 시 지도 중앙 이동 + 경로까지 점선, 소개·경로 거리·추가 시간 표시, **들르기**로 경유지 추가(보라색) | 동작 (11/15 확인) |
| 경로 | 고른 경로를 **Pleos 기본 내비에 경유지로 전달**하여 안내 시작 + 주행 기록 동시 시작 | 동작 (11/15 에뮬레이터 확인) |
| 주행 | 실시간 속도, 차량 전비·연비·누적거리·브레이크·주행모드 표시, 백그라운드 기록 | 동작 |
| 분석 | 출발 전 예측 vs 실제 소비, 급가속·급감속, "부드럽게 달렸다면?" 물리 모델 가상 계산 | 동작 (에뮬레이터 값은 가짜) |
| 공통 | 색 범례(출발 파랑·도착 빨강·콕 노랑·명소 보라·경로 2색), 주행 중 조작 잠금, 데모/실제 데이터 구분 표시 | 동작 |

## 3. 구조

```
app/src/main/java/com/example/gilkok/
├─ MainActivity.kt          화면 전체 (경로/주행/분석 탭, 비교 카드, 명소 목록)
├─ KokPoint.kt              콕 지점·명소 경유지 모델, 저장, 최적 방문 순서
├─ RouteEngine.kt           RouteProvider(OSRM 기본 / 데모 / 카카오), KokValidator, 도로 이름(KokNamer)
├─ PoiProvider.kt           명소: TourPoiProvider(TourAPI) / DemoPoiProvider, PoiRanker(정렬 규칙)
├─ RouteEnergy.kt           경로별 예상 에너지, 주행 후 실제값, 예측 저장
├─ MapProvider.kt           MapLibre 지도 + 경로·점 레이어 + 명소 오버레이 뷰
├─ NaviClient.kt            Pleos NaviHelper 연동 (경유지 FIRST/SECOND)
├─ VehicleTelemetry.kt      Pleos Vehicle SDK + AAOS 속도·주행 제한
├─ TripRecordingService.kt  주행 기록 foreground service (SDK 리스너의 단일 소유자)
├─ TripStore.kt             주행 기록 저장, TripAnalyzer(급가속·급감속)
├─ EnergyModel.kt           차량 물리 모델 (가상 시나리오)
└─ ExternalServices.kt      외부 통신(OkHttp), 지도 이용 동의
```

### 데이터 출처
| 용도 | 출처 | 키 | 비고 |
|---|---|---|---|
| 지도 | OpenStreetMap 타일 + MapLibre | 없음 | 공용 서버는 시험용. 서비스 단계에선 교체 필요 |
| 경로 | OSRM 공개 서버 | 없음 | 실제 도로망, **교통정보 없음**. 실패 시 데모로 대체 |

| 도로 이름·검색 | Nominatim (OSM) | 없음 | |
| 차량 | Pleos Vehicle SDK 2.3.2, NaviHelper 3.0.5 | 없음 | 콘솔에서 "사용 가능" 항목만 사용 |

## 4. 확정된 결정과 이유

| 결정 | 이유 |
|---|---|
| 특정 다리 목록이 아니라 **지도 아무 곳이나 탭** | 다리를 코드에 고정하면 "내가 아는 길" 취지와 맞지 않음 |
| 콕 지점 **최대 2곳** (명소 포함) | NaviHelper 경유지 한도가 2개 |
| 콕 지점은 진행 방향 차로에, 80m 이내 도로에만 붙임 (OSRM bearings/radiuses) | 다리 위를 찍으면 반대 차로·다리 밑 도로에 붙어 유턴 경로가 생겼음 |
| 실제 안내는 **기본 내비**에 넘김 | Pleos 정책상 주행 중 안내는 기본 내비 담당. 앱 미리보기와 실제 안내 경로가 다를 수 있음을 화면에 고지 |
| 명소는 팝업이 아니라 **패널 목록 + 지도 번호 표시** | 지도를 보면서 거리를 판단하고 결정해야 함 |
| 명소 목록은 **이름 + 카테고리 + 거리·추가 시간**만, 이름을 누르면 **대표 사진 + 1~3줄 소개** 펼침 | 차량 화면 가독성 (팀 의견). TourAPI `firstimage`(https로 변환), `overview` 사용 |
| 콕 지점은 **도로 이름을 주인공**으로, "경로에 반영됨 ✓ / 지나지 못했어요 !"를 실제 검증 결과와 연결 | 항상 ✓만 보이면 신뢰가 깨짐 |
| 비교 화면은 **좌우 두 칸 + 결론 한 문장**("3분 더 걸리고, 0.24 kWh 더 필요해요") | 한눈에 판단 (팀 의견) |
| 고른 경로는 **맨 위 전용 레이어(`route-top`)에 한 번 더 그림** + 카드를 누르면 잠깐 굵어지는 강조 | 두 경로가 겹친 구간에서도 고른 경로 색이 보여야 함. 레이어 순서 변경은 경로가 사라지는 버그가 있어 금지 |
| **연비 = 공인 도심/고속 연비로 구간별 역산** (`FuelModel.kt`): 연료(L) = 도심 km ÷ 도심 연비 + 고속 km ÷ 고속 연비. 시연 차종 그랜저 하이브리드(공인 범위 중간값: 도심 16.85, 고속 17.4, 복합 17.15 km/L). 고속 = 경로 구간 속도 70km/h 이상(고속도로·자동차전용도로). 화면은 L 차이 + 도심/고속 비율만 | 연비 담당 팀원 제안. 설명하기 쉽고 공인 수치라 신뢰도 높음. 추후: 실제 누적 연비 보정 표시(`actualKmPerL`), 차종 선택, 전기차 |
| 주행·분석 화면은 **숨김** (코드 유지), 안내 시 주행 기록도 끔 | 2차 PT 전 재설계 예정 (가속·감속 습관 피드백) |
| **지도 좌우 분할 화면은 시안 검토 후 미채택** (11/15) | 지도가 작아지고 갈라지는 지점 비교가 오히려 어려움. 코드에서 제거함 |
| 명소 정렬: 추가 시간 짧은 순 → 경로 중간~도착 근처 → 사진 있는 곳, 15분 초과 제외 | 잠깐 들러도 부담 없는 곳이 위로 |
| 데모 값과 실제 값을 **항상 화면에 구분 표시** | 심사·신뢰. 가짜 값을 실제처럼 보이게 하지 않음 |
| 주행 기록은 **기기 안에만** 저장, VIN 미수집 | 개인정보·Pleos 보안 가이드 |
| **습관 피드백 변수는 가속·감속 두 가지만** (팀 합의) | 자동변속 차량에서 운전자가 통제할 수 있는 건 이 둘뿐. 날씨·노면은 차에서 못 받고 조언으로 쓸 수도 없음 |
| 정체 정도는 **피드백이 아니라 공정한 평가(보정)용**으로만 사용 | 막힌 날 운전을 습관 탓으로 잘못 평가하지 않기 위해. 속도 기록에서 산출 가능 |
| 가속은 **속도 변화로 계산** | SDK에 가속 페달 값이 없음. 브레이크는 밟음/안 밟음만 제공 |
| 내연·하이브리드·전기차 **모두 대응** | Pleos 첫 적용 차종이 그랜저(가솔린·하이브리드). SDK에 연비·전비 둘 다 있음 |

## 5. 개발 방향 (남은 일, 우선순위 순)

1. ~~명소 지도 표시·내비 연동 확인~~ — 11/15 에뮬레이터에서 기본 흐름 10개 항목 모두 정상 확인
2. **경로 품질 점검** — 콕 지점 근처 유턴(방향 150° 이상 꺾임) 감지 후 재계산, 과한 우회 경고. 카카오맵 대비 **경로 검증표**(시나리오 15개) 작성해 기획서에 첨부
3. **습관 피드백 확정** — 가속·감속 기반 항목: 급가속, 급감속, 불필요한 브레이크(브레이크 직후 재가속), 경제 속도 초과 구간. 정체 정도가 비슷한 지난 주행끼리 비교해 점수
4. **"부드럽게 달렸을 때" 기준선** — 내 차 누적 연비(SDK)로 보정한 물리 모델을 기준선으로 쓰고, 실제와의 차이를 "습관 때문에 더 쓴 양(원)"으로 표시. 차종별(내연·하이브리드·전기) 파라미터
5. **시연 준비** — 가상 주행 기록 15회 정도를 넣어 피드백·보정 흐름이 보이게 (화면에 "시연용 기록" 표시), 시연 영상 녹화
6. (선택) 서울 TOPIS 실시간 도로 속도로 경로 시간 보정, 내비로 넘긴 뒤 남은 거리 비교로 "콕 경유 확인됨" 표시, 차분한 지도 스타일

## 6. 개발 환경과 실행

- Android Studio + **Pleos Connect v2.1.0 에뮬레이터 (API 34)**. minSdk 28, compileSdk 37
- **SDK Platform 37 설치 필수:** `Tools → SDK Manager → SDK Platforms → Android 37` 체크 후 설치. 차량 API(`android.car.jar`)를 여기서 가져오므로 없으면 빌드 실패
- 첫 빌드 때 인터넷 필요 (Pleos SDK 저장소 `nexus-playground.pleos.ai`, MapLibre 등 다운로드)
- 빠른 반영: 에뮬레이터를 켠 상태에서 `새로고침.bat` 더블클릭 (빌드 → 설치 → 앱 재실행)
- 테스트: `./gradlew test` (`RouteEngineTest`, `EnergyModelTest`, `TripAnalyzerTest`)
- 키: `local.properties`에 `TOUR_API_KEY=...` (저장소에 올리지 않음). 제출용 서명은 `RELEASE_STORE_FILE` 등 (`app/build.gradle.kts` 참고)

## 7. 알려진 함정 (같은 실수 반복 금지)

- **에뮬레이터 기본 위치는 미국 캘리포니아.** 한국 밖 좌표는 무시하고 데모 출발지(성수역)를 씀. 실제 위치처럼 쓰려면 에뮬레이터 `⋯ → Location`에서 서울 지정
- **에뮬레이터에 새 빌드가 안 깔리는 경우**가 있었음. 설정 화면 제목의 버전(`설정 · 버전 1.1`)으로 확인. 안 바뀌면 앱 삭제 후 재설치
- **MapLibre 데이터 기반 표현식(`Expression.get(...)`으로 굵기·크기 지정)이 이 환경에서 동작하지 않았음** → 경로가 얇게, 명소 점이 안 보였음. 고정값 + 레이어 분리로 해결
- **지도 글꼴(glyphs) 기반 텍스트도 안 보였음** → 명소 번호·이름은 지도 위 안드로이드 뷰 오버레이로 그림 (`MapProvider.rebuildOverlay`)
- **레이어를 지웠다 다시 붙이면 사라짐** → 레이어 순서 변경 코드 금지. 고른 경로를 위로 보이게 하려면 `route-top` 레이어에 그 경로를 다시 그리는 방식 사용 (`MapProvider.draw`)
- `values/themes.xml`의 `Gilkok.Title` 같은 점 이름 스타일은 `parent=""` 필수 (없으면 빌드 실패)
- `app/build.gradle.kts`에서 `java.util.Properties`를 직접 쓰면 오류 → 맨 위 `import java.util.Properties`
- **Kotlin 문자열에서 변수 뒤에 한글이 바로 붙으면 `${변수}`로 감쌀 것.** `"+$dt분"`은 `dt분`이라는 변수로 읽혀 빌드 실패함 → `"+${dt}분"`
- `새로고침.bat` 빌드 기록은 `build/last-build.log`에 남음. 에뮬레이터가 꺼져 있으면 설치 단계에서 실패하므로 먼저 켤 것
- 에뮬레이터가 무거워서 가끔 강제 종료됨. Device Manager에서 다시 켜면 됨
- 주행 중(`CarUxRestrictions`)에는 대부분의 조작이 잠김. 에뮬레이터 기어가 P인지 확인

## 8. AI에게 작업 맡길 때

- 먼저 이 문서와 `README.md`를 읽게 할 것
- 답변·주석은 **한국어**
- 메인 기능(길 콕 찍기·비교)을 해치는 변경은 하지 말 것. 보조 기능은 화면을 복잡하게 만들지 말 것
- 데모 값은 반드시 화면에 데모라고 표시

## 실시간 교통 (서울 TOPIS) — 켜짐 (링크 5,265개)
- 코드: `SeoulTraffic.kt` (`ENABLED = true`). 경로 구간 → 도로 링크 매칭 → 서울시 `TrafficInfo` 속도 조회 → 시간·정체 비율·고속 거리 재계산.
- 키: `local.properties`의 `SEOUL_TRAFFIC_KEY` (서울 열린데이터광장 일반 인증키, 깃 업로드 금지). API는 xml만 지원, http(8088)라 `network_security_config.xml`에서 해당 도메인만 평문 허용.
- 링크 모양: `assets/seoul_links.bin` = 서울시 TOPIS 링크 좌표 (`LinkVerInfo`). 만드는 법:
  1. `tools/교통링크_받기.bat` 실행 → 도로 514개(`LinkWithLoad`) → 링크 목록 → 좌표 → `tools/topis_raw.txt` (깃 제외)
  2. `python3 tools/make_topis_links.py` → GRS80 TM → 위경도 변환해 asset 생성
  - 국토부 표준링크 ID는 TOPIS ID와 달라 쓰지 않음 (`tools/make_seoul_links.py`는 참고용)
- 표시: 경로 카드에 "정체 구간 N%"/"막힘 없음", 비교 헤더에 "서울 실시간 교통 반영", 결론 아래 반영 구간 비율.
